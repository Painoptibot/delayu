**Дата:** 2026-07-24  
**Статус:** draft for review

## 1. Цель

Создать в «Делаю» подсистему учёта и сопровождения инвестиционных проектов Краснодарского края как **единый контур** для профильного департамента края (экономика / инвестиции — org в seed), АНО «Агентство по привлечению инвестиций» и муниципалитетов (МО).

Этап 1 даёт рабочий функционал сбора информации, оснастку сопровождения и автоматизацию внутренних процессов **без** живых интеграций Битрикс24 и СМЭВ (они — следующие этапы, с заделом в модели).

---

## 2. Решения (зафиксировано)

| Вопрос | Решение |
|--------|---------|
| Назначение этапа 1 | Учёт и сопровождение инвестпроектов + площадок/ЗУ |
| Состав MVP | Проекты, площадки, стадии, roadmap/SLA, роли, пакет/чек-лист, дашборд, импорт/сверка МО |
| Битрикс | Позже; сейчас самостоятельный контур в «Делаю» |
| СМЭВ | Позже (все релевантные сервисы сбора/актуализации); в этапе 1 — только задел |
| Заказчик/оператор | Единая подсистема: Департамент + Агентство + МО, разные роли |
| Воронки | Две связанные: привлечение (Агентство) и сопровождение/контроль (Департамент + МО), с handoff |
| Проект ↔ площадка | 1 проект → много площадок; бронь без коллизий |
| Подход реализации | Гибрид: кастомный домен invest + модули платформы |

**Вне scope этапа 1:** живые СМЭВ/Битрикс, публичный ЛК инвестора, полноценная ГИС-карта, замена INVEST-ID.

## 3. Архитектура

### 3.1. Идентификация подсистемы

- `Subsystem.code`: `invest-kk` (рабочее; уточняется при seed)
- `industry_template`: `invest`
- Наименование: «Инвестконтур Кубани» (или согласованный бренд с заказчиком)

### 3.2. Слои

1. **Платформа «Делаю»** — Organization, Role, membership, ModuleCatalog, вложения, уведомления, отчёты, импорт Excel, аудит, меню, platform console.
2. **Домен invest (кастом)** — проекты, площадки, связи/бронь, handoff, roadmap/SLA, пакет документов, batch импорта.
3. **Точки расширения** — `external_ids` / sync-хуки под Битрикс и СМЭВ (без реализации клиентов в этапе 1).

### 3.3. Участники

| Контур | Организация | Функция |
|--------|-------------|---------|
| Край / Департамент | org типа dept | Воронка сопровождения, accept/return handoff, полный дашборд |
| Агентство | org типа agency | Воронка привлечения, подбор/бронь, пакет к передаче |
| МО | org типа municipality (много) | Свои проекты/площадки, актуализация, импорт выгрузки |
| Админ подсистемы | — | Роли, справочники стадий, шаблон чек-листа |

Данные scoped по `subsystem`. Видимость: МО — своя org; Агентство/Департамент — весь subsystem.

## 4. Модель данных

Все сущности ниже связаны с `Subsystem` (прямо или через FK на project/site).

### 4.1. Сущности

| Модель | Назначение |
|--------|------------|
| `InvestProject` | Инвестпроект: код, название, инвестор, отрасль, МО, воронка (`attraction` / `support`), стадия, ответственный, показатели (инвестиции, рабочие места), `external_ids` (JSON) |
| `InvestSite` | Площадка/ЗУ: кадастр, МО, площадь, ВРИ/категория, координаты (опц.), статус объекта, % полноты карточки, `external_ids` |
| `InvestProjectSite` | Связь: `candidate` / `proposed` / `booked` / `selected` |
| `InvestHandoff` | Передача attraction→support (и возврат): инициатор, решение accept/return, комментарий, timestamps |
| `InvestRoadmapItem` | Этап дорожной карты: due_at, статус, ответственный; просрочка → дашборд |
| `InvestPackage` | Пакет документов по проекту (один активный на handoff-цикл) |
| `InvestPackageItem` | Элемент чек-листа: код шаблона, статус `missing` / `pending` / `attached` / `overdue`, вложение |
| `InvestImportBatch` | Импорт Excel от МО: файл, статус, diff-результаты |
| `InvestImportRow` (опц.) | Строка diff: действие new/changed/gap, решение apply/skip |

Справочники (seed + админ): стадии воронок, статусы площадок, шаблон пунктов пакета (логика Приложения 1: ЕГРН, ИСОГД, РГИС, запросы ОИВ, Контур.Фокус, анкета, меры ГП, протокол о намерениях и т.п.).

### 4.2. Стадии (стартовый seed, настраиваемые)

**Привлечение:** `lead` → `qualify` → `site_pick` → `package_ready` → `handoff`  

**Сопровождение:** `accepted` → `land` → `permits` → `build` → `commission` → `archive`  

**Площадка:** `draft` → `in_review` → `actual` → `archived` (бронь отражается в `InvestProjectSite`, не отдельным «вечным» статусом объекта, кроме UI-индикатора)

### 4.3. Инварианты

1. На одну площадку не более одной активной связи со статусом `booked` или `selected`.
2. Смена воронки проекта только через `InvestHandoff`, не прямым edit поля `funnel`.
3. Accept handoff запрещён, если обязательные пункты пакета в статусе `missing` (порог настраиваемый; default — все required).
4. Импорт не перезаписывает поля без подтверждения строки.
5. Площадку с активной бронью нельзя удалить; только снять бронь / archive по правилам.

---

## 5. Потоки

1. **Привлечение:** создать проект → кандидаты площадок → proposed → booked (с проверкой коллизии) → selected → закрыть чек-лист → создать handoff.
2. **Передача:** Агентство отправляет → Департамент accept или return с причиной → при accept: `funnel=support`, стадия `accepted`, создаётся roadmap сопровождения.
3. **Сопровождение:** движение по стадиям; МО обновляют территориальные данные; просрочки roadmap на дашборде.
4. **Импорт МО:** Excel → batch → diff → построчный apply.
5. **Дашборд:** воронки, SLA/просрочки, готовность пакетов %, брони, узкие места по МО/отрасли; выгрузка к совещанию.

## 8. Использование платформы (гибрид)

| Потребность | Платформа | Кастом |
|-------------|-----------|--------|
| Org, роли, membership | да | — |
| Модули каталога, лицензии | да | набор кодов для invest |

| Уведомления (просрочки, handoff) | да | события invest |
| Отчёты / Excel export | да | срезы дашборда |
| Импорт Excel | сервисы платформы + | parse/diff/apply invest |
| Меню по template | `menu.py` | блок `invest` |
| Аудит действий | да | ключевые операции брони/handoff/import |

Файлы (ориентир, уточняется планом): `models_invest.py`, `services/invest_*.py`, `views_invest.py`, `seed_invest_kk.py`, шаблоны `templates/invest/`, тесты `tests/test_invest_*.py`, миграция + choice `industry_template=invest`.

## 9. Ошибки и граничные случаи

| Ситуация | Поведение |
|----------|-----------|
| Бронь занятой площадки | HTTP/form error: кто держит бронь |
| Accept при неполном пакете | отказ со списком дыр |
| Прямая смена funnel | запрещена в API/форме |
| Импорт конфликтного поля | строка в review, не silent write |
| Удаление забронированной площадки | запрет |
| Пользователь МО чужой org | 403 / пустой queryset |

## 10. Тестирование (минимум)

- Инвариант брони (один active booked/selected на site).
- Handoff accept/return и смена воронки.
- Scope МО vs dept/agency.
- Import batch: diff + apply/skip.
- Пакет блокирует accept при missing required.
- Дашборд: подсчёт просрочек roadmap.
- Seed: подсистема, orgs, роли, демо проекты/площадки.

---

## 11. Дорожная карта после этапа 1 (не в этом спеке)

1. СМЭВ: сервисы сбора/актуализации (ЕГРН и др. по согласованному перечню) → автозаполнение/мониторинг площадок и проектов.  
2. Битрикс24: двусторонняя синхронизация сделок/объектов.  
3. Витрина/ЛК инвестора, усиление INVEST-ID.  
4. ГИС-слой, пакетные запросы в ОИВ, тепловые карты.

---

## 12. Критерии готовности этапа 1

- Подсистема `invest` поднимается seed-командой с демо-данными.  
- Три типа пользователей (agency / dept / mo) проходят свой основной сценарий end-to-end.  
- Дашборд показывает живые агрегаты без ручного Excel.  
- Инварианты брони и handoff покрыты тестами.  
- Нет зависимости от Битрикс/СМЭВ для работы этапа 1.
